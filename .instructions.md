# GitHub Copilot Instructions - SAE4 DWeb-DI.01 Social

## 🎯 Architecture Générale du Projet

Ce projet suit une **architecture en couches** avec séparation claire entre présentation (UI) et logique métier (UX/Store).

### Structure des Composants

```
frontend/src/component/ui/
├── atoms/           # Composants primitifs réutilisables (Avatar, Button, Icon, etc.)
├── shared/          # Composants partagés cross-domaine (FollowButton, LikeButton, etc.)
├── features/        # Composants métier organisés par domaine
│   ├── tweet/       # Domaine Tweet
│   ├── profile/     # Domaine Profile
│   ├── post/        # Domaine Post
│   ├── navigation/  # Domaine Navigation
│   └── register/    # Domaine Register
├── animations/      # Helpers pour motion.dev
├── containers/      # Composants connectés au store (logique)
└── store/           # Gestion d'état centralisée
```

## 📋 Conventions de Code

### 1️⃣ Composants UI (Dumb Components)
- **Localisation** : `atoms/`, `shared/`, `features/*/`
- **Caractéristiques** :
  - ✅ Props-driven (reçoivent tout par paramètres)
  - ✅ Pas de logique métier
  - ✅ Pas d'appels API directs
  - ✅ Pas de connexion au store
  - ✅ Réutilisables et testables
  - ✅ Sont les **responsables du style et de l'animation**

**Exemple** :
```tsx
interface TweetProps {
  content: string;
  author: { username: string; id: string };
  likes: number;
  onLike?: () => void;
}

export function Tweet({ content, author, likes, onLike }: TweetProps) {
  return (
    <div>
      <p>{author.username}</p>
      <p>{content}</p>
      <button onClick={onLike}>{likes} likes</button>
    </div>
  );
}
```

### 2️⃣ Containers (Smart Components)
- **Localisation** : `containers/`
- **Caractéristiques** :
  - ✅ Connectés au **store** pour fetch/update data
  - ✅ Orchestrent la logique métier
  - ✅ Passent les données transformées aux composants UI
  - ✅ Gèrent les appels API et side effects
  - ✅ Peu/pas de styling direct

**Exemple** :
```tsx
import { useTweetStore } from '../store/tweetStore';
import { Tweet } from '../ui/features/tweet/Tweet';

export function TweetContainer({ tweetId }: { tweetId: string }) {
  const { tweets, likeTweet } = useTweetStore();
  const tweet = tweets.find(t => t.id === tweetId);

  if (!tweet) return null;

  return (
    <Tweet
      content={tweet.content}
      author={tweet.author}
      likes={tweet.likes}
      onLike={() => likeTweet(tweetId)}
    />
  );
}
```

### 3️⃣ Store Pattern + Authentification

**Localisation** : `store/`  
**Outils** : Zustand (gestion d'état) + Token API Simple (authentification Symfony)

#### Structure du Store
```
store/
├── types.ts              # Types TypeScript (User, Post, etc.)
├── api-client.ts         # Helper centralisé pour appels API
├── index.ts              # Exports principales
├── slices/
│   ├── authSlice.ts      # Auth + Token Management
│   ├── postSlice.ts      # Posts + Like/Repost
│   ├── userSlice.ts      # Users + Follow
│   └── uiSlice.ts        # UI State
├── hooks/
│   ├── useAuth.ts        # ✅ Login/Logout
│   ├── usePosts.ts       # ✅ Posts management
│   ├── useUsers.ts       # ✅ User relations
│   └── useUI.ts          # UI state
├── SIMPLE_TOKEN_SYSTEM.md # 📖 Lire en PREMIER
└── JWT_REMOVAL_SUMMARY.md # Détails des changements
```

#### Authentification

**Système** : Token API simple (pas JWT)
- Login avec `/api/login_check` (Symfony endpoint)
- Token brut sauvegardé en localStorage
- Automatiquement inclus dans tous les appels API
- Backend valide en hashant et comparant avec la BD

**Usage** :
```typescript
// Hook authentification
const { user, token, isAuthenticated, login, logout } = useAuth()

// Login
await login('john', 'password123')

// Token inclus automatiquement dans tous les appels
const posts = await apiCall('/posts')  // ✅ Authorization header auto-ajouté
```

#### Appels API

Utiliser le helper centralisé `apiCall()` qui gère automatiquement :
- ✅ Token en Authorization header
- ✅ Content-Type JSON
- ✅ Gestion des erreurs

```typescript
// Import
import { apiCall } from '@/store'

// GET (token inclus auto)
const posts = await apiCall<Post[]>('/posts')

// POST
const newPost = await apiCall<Post>('/posts', {
  method: 'POST',
  body: JSON.stringify({ content: '...' })
})

// DELETE
await apiCall(`/posts/${id}`, { method: 'DELETE' })
```

#### Convention de nommage
- `use*Store()` pour les hooks store (ex: `useAuthStore()`)
- `use*()` pour les hooks custom (ex: `useAuth()`, `usePosts()`)
- Fichiers slices: `*Slice.ts` (ex: `authSlice.ts`)

## 🎨 Design System & Responsive

### Mobile-First
- ✅ Design d'abord mobile
- ✅ Breakpoints Tailwind : `sm`, `md`, `lg`, `xl`, `2xl`
- ✅ Préfixer les classes desktop : `md:`, `lg:`, etc.

**Exemple** :
```tsx
<div className="w-full md:max-w-[600px] lg:max-w-[800px]">
  {/* Mobile par défaut, s'étend sur tablette/desktop */}
</div>
```

### Animations
- **Librairie** : [motion.dev](https://motion.dev/docs)
- **Localisation des helpers** : `ui/animations/`
- **Convention** : Préfixer les hooks animation avec `useMotion*`

**Exemple** :
```tsx
import { useMotionAnimation } from '../animations/useMotionAnimation';

export function AnimatedButton() {
  const { variants, transition } = useMotionAnimation('fadeInUp');
  return <motion.button variants={variants} transition={transition}>Click</motion.button>;
}
```

## 📝 Checklist pour Créer un Nouveau Composant

1. ✅ **Décider du type** : Atom / Shared / Feature / Container ?
2. ✅ **Placer le fichier** : Respect de l'arborescence
3. ✅ **Définir les props** : Interface TypeScript stricte
4. ✅ **Ajouter du styling** : Tailwind mobile-first
5. ✅ **Prévoir l'animation** : motion.dev
6. ✅ **Exporter dans l'index** : `atoms/index.ts`, `shared/index.ts`, etc.
7. ✅ **Connecter au container** : Si logique métier nécessaire
8. ✅ **Tester** : Storybook / Tests unitaires (futur)

## 🚀 Bonnes Pratiques

### DO ✅
- Prioriser la **réutilisabilité** des composants UI
- Passer les **données par props** dans l'UI
- Utiliser le **store pour l'état global** (user, tweets, etc.)
- Nommer les fichiers avec `PascalCase`
- Documenter les interfaces TypeScript
- Penser **mobile-first** en CSS

### DO NOT ❌
- Ne pas mélanger logique métier et présentation
- Ne pas faire d'appels API dans les composants UI
- Ne pas créer de dupliquer de composants (importer au lieu de dupliquer)
- Ne pas utiliser `any` en TypeScript
- Ne pas ignorer les types de données volumineux
